# Cyanium design-sync notes

## Shape & build
- **Package shape** (`cfg.shape: "package"`), pkg `@cyanium/ui`, global `window.CyaniumUi`.
- The repo's Storybook is **gallery-organized** (titles = atomic tiers, each story composes many components), so it can't produce per-component previews — that's why we use the package shape, not storybook shape.
- **Resolution root for the converter is `apps/docs/node_modules`** (NOT `packages/ui/node_modules`). pnpm is strict/non-hoisted; only `apps/docs` has symlinks to BOTH `@cyanium/ui` and `@cyanium/kits` plus react/react-dom/lucide-react. All three react symlinks share one realpath, so esbuild dedups (no duplicate-React).
- Build: `node .ds-sync/package-build.mjs --config .design-sync/config.json --node-modules apps/docs/node_modules --entry packages/ui/dist/index.js --out ./ds-bundle`
- `buildCmd` runs the pnpm package build AND a Tailwind v4 compile (see CSS below).

## CSS (Tailwind v4)
- `packages/ui/src/styles.css` is **Tailwind v4 source** (`@import "tailwindcss"`), NOT compiled CSS. The converter appends `cfg.cssEntry` verbatim, so it needs real compiled CSS.
- We compile `.design-sync/css-entry.css` (imports the ui styles + adds a `@source` scan for `packages/kits/src`) to `packages/ui/dist/_ds-compiled.css` via `npx @tailwindcss/cli@4`. `cfg.cssEntry: "dist/_ds-compiled.css"` (must live inside the package dir — cssEntry is PKG_DIR-bounded). Regenerated by `buildCmd` on every sync.

## Fonts
- DS uses **Inter** (sans/display) + **DM Mono** (mono), loaded from Google Fonts CDN in the repo. We ship self-contained woff2 (from @fontsource) in `.design-sync/fonts/` with `.design-sync/fonts/fonts.css`, wired via `cfg.extraFonts`. Resolves `[FONT_MISSING]`.

## Kits
- The 3 kit templates (`FinanceApp`, `LandingPage`, `AiChatApp`) come from `@cyanium/kits`. `extraEntries: ["@cyanium/kits"]` merges them into the bundle global; `componentSrcMap` adds them as component cards (pinned to their `packages/kits/src/.../*.tsx` source). The `*Demo` variants and namespace exports (`finance`, `landing`, `ai`, `patterns`, `fixtures`) are intentionally not separate cards.
- esbuild prints harmless `[ignored-bare-import]` warnings for kits' CSS side-effect chunks (`sideEffects: ["**/*.css"]`) — component CSS already ships via the compiled stylesheet.

## Authoring previews — composition sources
- **The Storybook stories ARE the canonical composition source.** `apps/docs/src/stories/*.stories.tsx` use the real DS API with exact props. Port their JSX. Key files: atoms, button, input, molecules, organisms, organisms-new, foundations.
- Kit fixtures: `@cyanium/kits/fixtures` (financeCards, budgetStats, financeMainNav, financeUser, financeBrand, budgetChartData/Months, financeTopbar…) and `@cyanium/kits/patterns` (StatCard, NavItem, TransactionRow, AppSidebar, AppTopbar, StatusBadge) hold realistic data/sub-components.
- Import components from `'@cyanium/ui'`; icons from `'lucide-react'` (resolves & tree-shakes fine in preview builds).
- Use the DS's Tailwind utility classes for layout glue (`text-text-sub`, `text-text-strong`, `bg-bg-weak`, `border-stroke-soft`, `gap-*`, `size-5`, `space-y-*`, `w-80`) — they resolve from the shipped compiled CSS.

## Known component API notes (from solo calibration — all graded good)
- `Button`: `intent` primary|neutral|error, `variant` filled|stroke|lighter|ghost, `size` xsmall|small|medium|large, `leadingIcon`/`trailingIcon`/`iconOnly` (+ `aria-label` for iconOnly).
- `Input`: `label`, `placeholder`, `hint`, `error`, `leadingIcon`/`trailingIcon`, `type`, `disabled`.
- `Card`: compound — `Card` (`raised`, `padding` none|md|lg) + `CardHeader`/`CardTitle`/`CardDescription`/`CardContent`/`CardFooter`.
- `Heading`: `level` h1–h6. The DS type scale is intentionally **restrained** (utilitarian brand voice) — heading levels render with modest size differences; that's faithful, not a bug.
- primary intent renders **blue** (DS default theme); the brand mark is orange. Both are correct DS output.

## CSS: dynamic Badge color classes (RESOLVED)
- `badge.tsx` builds color classes by string interpolation (`bg-[var(--${color}-500)]`, `bg-[var(--${color}-200)]`, `bg-[var(--${color}-50)]`, `text-[var(--${color}-600/900)]`, `shadow-[inset_0_0_0_1px_var(--${color}-200)]`) over colors blue/orange/red/green/yellow/purple/sky/pink/teal. Tailwind's static scanner can't see interpolated arbitrary values, so those classes were missing from the compiled CSS.
- **Fix (in `.design-sync/css-entry.css`):** `@source inline(...)` directives force-generate the full Badge color × shade matrix (shades 50/200/500/600/900). If badge.tsx adds colors/shades, extend those directives.
- ProgressBar (`bg-primary`/`bg-success` + inline SVG stroke vars) and Avatar (literal `bg-[var(--blue-200)]` etc.) use static/literal classes — no safelist needed.

## Component API quirks (from wave-1 authoring — all graded good)
- `RadioControl` renders dot-only → wrap each in a `<label>` for text; `Checkbox` has a built-in `label` prop. Indeterminate Checkbox needs `indeterminate` + `defaultChecked="indeterminate"`.
- `Slider` range = two-element `defaultValue` array (+ `minStepsBetweenThumbs`). `Select` `options` = `{value,label,disabled?}[]` (label is a string). `Textarea` `showCounter` requires `maxLength`.
- `Tabs`/`SegmentedControl` take an `items` array; compose `TabsContent value=…` children for panel content. `Breadcrumb`/`Pagination` are data-driven (`items`, `total`+`page`).
- `Subheading` sizes are `2xs|xs|sm` (uppercase tracked label). `Eyebrow` = children-only label with a leading blue dot (faithful). `Kbd` renders a DM Mono keycap.
- `FeatureCard`/`EmptyState`/`SectionHead` are self-contained (no wrapping Card). `EmptyState` takes `action` node OR `actionLabel`+`onAction`.
- Vertical `Separator` needs an explicit `h-*`/`w-px` className to be visible.
- `Field` wraps a bare control (`InputControl`), not `Input`.
- Closed/static states are sufficient for all form controls — no `cardMode` overrides needed for wave 1.

## Overlays & capture limitation (wave 2)
- `Modal` and `Dialog` accept a controlled `open` boolean → render fully open with `open={true}` (graded good). `DialogContent` wraps its own Portal+Overlay (don't nest `DialogPortal`/`DialogOverlay`).
- **`Dropdown`, `DropdownMenu`, `Tooltip` can't show their open surface in capture**: the capture pipeline does no hover/click, and these wrappers don't forward `open`/`defaultOpen` (and `DropdownMenuContent`/`Item` aren't exported). The components are fully functional in the bundle (correct `.d.ts`/`.prompt.md`); their cards show the **closed trigger only** — a faithful static state, not a defect. Graded good-with-note (closed state). To capture open surfaces later, the DS would need to forward `defaultOpen` on these wrappers, or the capture step would need an interaction hook.
- `cfg.overrides` cardMode applied: Modal/Dialog/Dropdown/DropdownMenu/Tooltip = `single` (overlays use `fixed inset-0`); FinanceApp/AiChatApp = `single` 1200x800; LandingPage/MarketingShell = `single` 1200x600.
- **`column` cardMode** (story renders wider than the default grid cell → `GRID_OVERFLOW`): DataTable + Accordion, Alert, Banner, EmptyState, Eyebrow, FeatureCard, Heading, Pagination, Panel, ProgressBar, RadioGroup, SectionHead, SegmentedControl, Switch, Tabs, Text, Textarea. These surfaced only on a clean coherent validate (a concurrent build had masked them). Fix is presentation-only: add `{"cardMode":"column"}`, `preview-rebuild.mjs --components …`, grades carry, no re-validate needed.
- **`Icon` trips `RENDER_THIN`/`allHollow` and it's benign**: icon-only cells have no text and ~24px height, but the SVGs paint (render-check `bad:false`, pngBytes ~12KB). Graded good; do NOT "fix" by padding the preview.

## Kit apps & more API notes (wave 2)
- Kit apps (`FinanceApp`/`LandingPage`/`AiChatApp`) are NOT in `@cyanium/ui` — their previews import from `@cyanium/kits/{finance,landing,ai}`. Simplest faithful render: `build{Finance,Landing,AiChat}AppProps()` from `@cyanium/kits/fixtures` (same data the `*Demo` wrappers use). Their capture sheets land under kit group prefixes (`finance__`, `landing__`, `ai__`), not `general__`.
- `MarketingShell` (`@cyanium/ui`) is a thin wrapper (`min-h-screen bg-bg-white` + optional `nav` slot); compose a hero/sections from DS primitives.
- Token: DS white surface is `bg-bg-white` (NOT `bg-bg-white-0`).
- `Accordion` `type` is required (`single`+`collapsible`+`defaultValue="x"`, or `multiple`+`defaultValue={[...]}`). `SearchField` injects a Search icon + `shortcut` Kbd (default "⌘K"; `shortcut=""` suppresses). `RowActions` is a lone icon button — compose inside a realistic row.

## Re-sync risks (watch-list for the next sync)
- `_ds-compiled.css` is a build artifact (gitignored under `dist/`); `buildCmd` must run before the converter or `cfg.cssEntry` won't exist. The driver runs `buildCmd` automatically.
- Fonts are a curated latin subset of Inter/DM Mono. If the DS adds glyphs/weights, extend `.design-sync/fonts/`.
- Kit cards depend on `componentSrcMap` paths into `packages/kits/src` — if kit source moves, update the map.
- Overlay components (Dialog/Modal/Dropdown/Tooltip) and wide ones (DataTable/MarketingShell/kit apps) may need `cfg.overrides.<Name>.cardMode` — see grades. The full `column` set is enumerated under "Overlays & capture limitation" above.
- **Never run two builds against `./ds-bundle` concurrently.** `package-build.mjs` clears `components/`/`_ds_sync.json` at start; an overlapping build (or a still-running background build from a prior turn) leaves a half-cleaned bundle and a *partial* validate that silently under-reports warnings (e.g. masked the 17 `GRID_OVERFLOW`). Before launching a build, confirm none is running (`pgrep -f "ds-sync/package"`).
- `cfg.readmeHeader: "conventions.md"` prepends `.design-sync/conventions.md` (repo-authored agent guidance) to the bundle README. Keep it well under ~31,900 chars or the generated body gets truncated to zero.
